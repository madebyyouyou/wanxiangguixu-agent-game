# 渡厄镇 · 随行系统 程序对接说明

> 本文档**面向程序**，不是给大模型的 prompt。它说明：怎么把三套人格 prompt 接进游戏、每轮喂什么状态、怎么解析模型输出、以及一系列只能由程序保证的机制（危险拦截、回溯、安全审核、兜底等）。
>
> 配套文件：`Agent_System_Base.md`（公共底座）+ `Agent_System_1_QueShe.md` / `Agent_System_2_WuYou.md` / `Agent_System_3_ShuHeng.md`（三套人格）。

---

## 0. 一句话架构

> **系统提示 = 公共底座 + 玩家所选的那一份人格文件**（拼接而成，整段作为 system prompt）。模型**无状态**、不记进度；它每一轮的认知，完全等于**程序当轮喂给它的状态**。所以"对不对、超不超前、剧不剧透"，全取决于程序喂的对不对。

---

## 1. 文件与加载

- 玩家在开局三选一里选定系统后，把 **底座 + 对应人格文件** 拼成一段 system prompt 传给模型。三套人格互不加载、互不知晓。
- **建议开启 prompt 缓存**：底座 + 人格这段是整个游戏都不变的，缓存它能显著省成本和首字延迟。每轮真正变化的只有下面第 3 节的"状态文本"。

---

## 2. 调用时机与触发

### 2.1 取状态的时机（关键，决定延迟与正确性）
**在"玩家点开对话框"的那一刻打包状态快照**，备着；等玩家真正发送时直接用这份快照 + 问题去调模型。这样把"打包 + 准备"塞进玩家打字的空当，省掉发送时的现采延迟。

> 前提：**玩家开着对话框时，剧情不会自己往前推进**（开对话框时，玩家不可点击剧情）。因此快照不会过时，**采用此"点开即打包、发送直用"方案即可**，无需发送时再校验。

### 2.2 触发模型说话的两种情况
1. **玩家说话**：玩家在对话框发送内容 → 带 `player_input` 调模型。
2. **程序在某节点请系统开口**：刚进新场景、刚发生关键事件时，程序**主动发起一次调用**（不带 `player_input`，带 `agent_directive`，见 3.2），让系统先说一句。
   - 这是常规的"程序在事件点 call 一次 API"，触发点不多，**精确钉在下面这几个节点**（见 2.3 表）。

> 注：`risk_alert`（危险拦截）**不属于上面两种触发**——它不调模型生成内容，只是事后同步给模型的一个字段。详见第 7 节。

### 2.3 主动开口触发表（程序在这些精确时刻 call 系统，带 `agent_directive`）

| 触发 | 类型 | 精确前置条件（程序在此刻 call 系统，附 `agent_directive`） |
| --- | --- | --- |
| T01 | 开场 | 进入副本、T01 主街 messagebox 剧情**播完后** |
| T11 | 引导 | T11 茶馆"虫茶其实是真温茶、那男人写'见'字"的 messagebox **播完后**；directive=引导"那男人为何提醒你" |
| T13 | 引导 | T13 剧情过到 **"这一夜，门外没有声音。"之后**；directive=引导"裂缝是什么" |
| T15 | 提示 | 玩家**在非祠堂地点尝试拖拽合成匕首、被扣清醒值之后**；directive=引导"声音太大/有东西被惊动了，去祠堂操作"（**此条不进 risk_alert**，只是普通的扣分后提示） |
| T17 | 引导 | T17 茶馆 **"你在脑子里过了一遍这个名字。"之后**；directive=引导玩家琢磨"杜司衡"这名字 |
| T18 | 引导 | T18 祠堂夜、推理推到 **"杜司衡是侥幸活下来、没被同化的外乡人？"之后**；directive=引导"红布会变暗、又撕不烂烧不掉，被同化外乡人的红布去哪了？杜司衡三十年的红布为何没失效？" |
| T24 | 复盘 | 副本结算动画**播完、进入元空间复盘界面**时；directive=复盘 |

**不主动开口的节点**：T22（纯推理节点，留给玩家自己整理，系统不弹）；T20 铭文（由玩家**主动点"扫描"**才触发，走 `agent_directive:扫描`，属玩家驱动，不在本表）。

## 3. 输入：每轮喂给模型的状态

### 3.1 程序内部用 JSON 存，喂进去前渲染成"带小标题的中文文本"
模型只吃文本。**建议程序内部用 JSON 维护状态，拼进 prompt 前渲染成带【】小标题的自然语言块**——对 DeepSeek 这类模型，比直接贴裸 JSON 更好读、更不易出错。

**字段契约**（带 `?` 的为可选，可能某轮没有）：

| 字段 | 说明 |
| --- | --- |
| `current_day` / `current_time` / `current_location` / `current_event` | 当前天数 / 时辰 / 地点 / 事件编号（如 T11） |
| `story_digest` | **已经历节点的逐句摘要数组**（长期记忆层，见第 4 节 + 附录 A）。只放玩家**已经过**的节点，按顺序 |
| `node_text` | **当前节点的剧情原文**（"现场"）。超长演出节点也给原文 |
| `agent_directive?` | 本节点程序交给系统的指令，见 3.2 |
| `collected_clues` | 已收集线索编号数组，如 `["M1","M2","M10"]` |
| `rules_book` | 已收录规则及真伪标记，如 `[{"id":"R1","mark":"存疑"},{"id":"R3","mark":"假"}]` |
| `sanity` | 清醒值 0–100 |
| `points` | 当前积分 |
| `inventory` | 背包道具数组，**每项带 `usage` 用法**，见第 9 节 |
| `shop_catalog` | 当前可兑换商品，含 `id`/`name`/`price`/`stock`/`effect`/`usage` |
| `op_hint?` | 当前可做的多步操作步骤提示，见第 9 节 |
| `last_action_result?` | 上一条购买指令的执行结果，见第 6 节 |
| `risk_alert?` | 危险拦截的事后同步（仅乌有），见第 7 节 |
| `rewind_flag?` | "刚发生回溯"信号，见第 8 节 |
| `player_input?` | 玩家这一轮说的话（程序主动触发时没有） |

### 3.2 `agent_directive` 的格式

**它是什么 / 程序逻辑**：`agent_directive` 就是"程序在某个剧情节点，主动塞给系统一条'这一句你该干嘛'的指令"。它**只在"程序主动请系统开口"那种调用里出现**（见 2.2 第②种触发、2.3 表）——也就是没有玩家发言、但程序想让系统说话的时候，用它告诉系统"现在是开场/引导/扫描/复盘"。玩家正常发言（第①种触发）时，**通常不带** `agent_directive`。

格式是带类型的对象：
带类型的对象，程序按节点投放：

```json
{"type":"开场", "text":""}                       // 让系统就当前场景说句开场白
{"type":"引导", "text":"那男人为何提醒你"}         // 让系统把玩家往这个方向引（只提问、不给答案）
{"type":"扫描", "text":"<井口石刻铭文原文>"}        // 让系统把这段"翻译"念给玩家（只念不解读）
{"type":"复盘", "text":""}                       // 进入结算复盘
```

### 3.3 渲染成文本的模板（建议格式）
程序把 JSON 渲染成这种块，作为每轮的 user 消息（或紧跟 player_input 之前）：

```
【当前进度】第3天·下午·茶馆（T11）
【已经历】
- T01 抵达渡厄镇，接到探查污染源、修复异常的任务
- T02 布庄无眼老妇给红布、说不收活人；你问"这是我的脸吗"，她说眼睛看到的不一定可信，给了你一根黑线头
- T03 自由探索见诸多怪事，发现镇子怎么走都绕回主街
- T04 远观井口，见红水违反重力上飘
- T05 夜里门外有脚步与刮门声、有人求开门，你没开
- T06 门现爪痕、捡到"天黑去井边"的纸条
- T07 裁缝铺女人把黑线头放窗台示意你拿
- T08 小女孩说"巳时买米、晡时饮茶"能防幻觉
- T09 回祠堂过夜，门外又诱你开门，没开，平安过夜
- T10 米店买米，老板报"八两"，掌心留下一阵清凉
【当前现场】下午，你准时出现在茶馆门口。刘爷爷从蒸汽后抬眼……（node_text 原文）
【已知线索】M1 渡厄镇不收活人；M10 井口红水违反重力；…
【已知规则】R1 日落闭户·红布挂门（存疑）；R3 天黑去井边（假）；…
【清醒值】75 【积分】15
【背包】红布（用法：日落挂门口、用铁钉固定）；生锈铁钉（…）
【本节点指令】引导：那男人为何提醒你
```
（玩家说话时，把玩家原话作为 `player_input` 紧随其后。）

## 4. 剧情分层打包（防止上下文膨胀）

每轮喂给模型的剧情分三层，**只有"当前一节"是重的**：

1. **已过节点逐句摘要（`story_digest`）** —— 长期记忆层（**素材见附录 A**）。规则：
   - 主线 T01–T24 **按编号严格顺序、必然全部经历**：玩家走到 T14，就一定踩过 T01–T14。所以 `story_digest` 就是 **T01 → 当前节点** 的连续摘要前缀。
   - **分叉节点只填玩家实际选的那一支**：附录 A 里把各分支变体都列出来供你查，但运行时**玩家选了哪支就只传哪支**，没选的那支模型不该知道（保持"模型只知道已发生的"）。
   - **隐藏节点按是否触发**：如 `T_hide01` 仅在 T02 选 B 时存在，没触发就不放。
   - **回溯**：见第 8 节——回溯时不删除回溯前的记录，而是**插一条 ⟳ 标记后继续往下记**。
2. **当前节点原文（`node_text`）** —— "现场"。**取值＝当前这个事件从触发起、到此刻文本框里已播出的全部剧情文本**（不是只最后一句）。**超长演出节点（死亡演出、T23 真相独白）也给原文**（DeepSeek V4 上下文足够）。
   - *可选优化（非必须）*：若实测发现"某段长演出后系统接话抓不准其中细节"，可把该节点临时改喂"事实摘要"代替原文。默认不做。

### 4.1 复盘节点（T24）的特殊注入：复盘真相包
T24 复盘是个特殊节点，它的 `node_text` **不是某段剧情原文，而是整份 `复盘真相包.md`**。规则：

- **时机**：副本结算动画**播完、进入元空间复盘界面**时注入。
- **对象**：当前所选的那个系统（底座 + 人格照常加载，不变）。
- **形式**：把 `复盘真相包.md` **整包作为 `node_text`** 注入，并带 `agent_directive: {"type":"复盘"}`。它比普通节点长，但只此一次、DeepSeek V4 装得下，不影响别处。注入后系统即"知道全部真相"，可开放回答玩家任意角度的提问。
- **推荐问题**：复盘界面给玩家的几个推荐问题（茶馆男女为何想帮我 / 按茶馆男人的规则走为何反而死 / 杜司衡为何救我 / 第六天米店的秤为何坏 / 时空管理局知道献祭真相吗），**由程序在界面上直接渲染成按钮/选项**，不必塞进 prompt。玩家点了哪个，就把该问题文本当作 `player_input` 发给系统；玩家也可自由输入别的问题。
- **口径**：真相包内已写明两处特殊口径——①"时空管理局是否早就打算牺牲玩家/是否与杜司衡合谋"这类戳到系统自身立场的追问，系统**含混其词、打哈哈揭过**；②情感余韵（杜司衡的留恋等）**系统不主动提**。系统照真相包执行即可。
- **红线**：复盘语境下剧情真相全解禁，但底座 §四（不出戏）、§五（内容红线）**仍然有效**。
3. **线索/规则编号清单（`collected_clues` / `rules_book`）** —— 紧凑的事实清单。

## 5. 输出：解析规则

模型一条回复，最多三段（**对白正文必有**，另两个按需）：

```
<state>紧张</state>对白正文……<action>{"type":"purchase","item_id":"ITEM_REWIND_CLOCK","qty":1}</action>
```

程序解析：
1. **抽 `<state>状态名</state>`**（可能没有）→ 驱动灵球动画。可能值：`兴奋`/`紧张`/`肯定`/`否定`（其余动画状态如待机/说话由前端自行处理）。一条最多一个。
2. **抽 `<action>{…json…}</action>`**（可能没有）→ 走第 6 节购买流水线。
3. **把这两个标签从文本里剥掉，剩下的"对白正文"才显示给玩家。**
4. **容错**：标签可能缺失、格式偶有偏差；解析要稳健（用宽松正则/try-catch），抽不到就当没有，别让整条回复因为标签问题不显示。

## 6. 购买流水线

1. 模型输出 `<action>{"type":"purchase","item_id":"<ID>","qty":<n>}</action>`。
2. **程序校验**：`item_id` 是否在 `shop_catalog`、积分是否够、库存是否够。
3. **执行**：扣积分、减库存、加入背包。
4. **回填 `last_action_result`**，下一轮注入给模型，例：
   ```json
   {"type":"purchase","item_id":"ITEM_REWIND_CLOCK","ok":true,"reason":"","points_after":-20}
   // 或失败：{"ok":false,"reason":"积分不足","points_after":15}
   ```
   模型据此用人话确认成功/失败（prompt 已要求它**不预报"买好了"**，只在拿到结果后确认）。
5. **库存/数量注意**：火柴可买多根（`qty>1`）；锻造火炉库存仅 1、秘鲁圣木香囊库存 3——**售罄要在 `shop_catalog` 的 `stock` 里反映出来**，模型才不会推荐已售罄的。

## 7. 危险拦截（`risk_alert`）——仅乌有

### 7.1 机制
- **风险检查与拦截弹窗，只在"玩家选了乌有"的局启用。** 雀舌/枢衡局不跑此逻辑。
- **本副本唯一的致命操作 = T08 分岔口"去井边"**（白天没喝茶就往井走，触发即死结局 `END_FANTASY_DEATH`）。玩家点击该操作时，**程序先不执行，直接弹出一句固定脚本警告**把玩家拦下。
- **这句警告是程序写死的固定脚本，不经过模型、不需要模型生成。**

### 7.2 固定脚本（语气参照）
拦"去井口"的脚本，语气参照：
> 站住——别往那口井边去！别问为什么，我浑身的汗毛都竖起来了，那个方向你绝对不能走。退回来，听我的。

（不解释后果——乌有"凭直觉硬拦"。）

### 7.3 ★记忆连续性（必须做，否则穿帮）
弹完固定脚本后，**必须把这句警告以"乌有"的身份追加进对话历史**，下次调模型时一并带上（或通过 `risk_alert` 字段告诉模型"宿主刚做了 X 操作 + 已弹的警告是 Y"）。
- 否则会断裂：弹窗是程序播的、模型没存进记忆 → 玩家下一句"多亏你拦我"，模型一脸懵"我拦你啥了"。
- 模型那边只需"认账记住"，prompt 已写明它不自己生成警告。

## 8. 回溯与循环记忆

- 「回溯钟」把时间拨回更早一天：**天数、清醒值、红布亮度等回退**；但 **`collected_clues` / `rules_book` / `inventory`（线索、记忆、道具）不回退**——玩家是"带着记忆重活一遍"。
- 回溯发生后，程序传 **`rewind_flag`** 信号；模型会顺着"我们又回到这儿了/再来一次"演（prompt 已写明这不算剧透，是共享记忆）。
- 回溯后**重发回溯后的正确快照**（天数/清醒值已回退，但 story_digest/线索按"玩家到过的最远处"保留）。

**`story_digest` 里怎么标回溯（重要）**：回溯**不擦除**回溯前走过的记录，而是**插一条 ⟳ 分隔标记、继续往下记**，让模型看到"走过→回溯→重走"的完整轨迹（它保留着回溯前学到的线索，所以能演出"带着记忆重来、这次换条路"）。程序侧维护一个"触发日志"数组，按真实发生顺序 append（含回溯标记），渲染时原样列出。示例：

```
【已经历】（按实际触发顺序；含回溯）
1. T02 布庄无眼老妇给红布、说"不收活人"，你问"这是我的脸吗"，她说眼睛看到的不一定可信，给了你一根黑线头
2. T04 去看井，见红水违反重力上飘
3. T05 祠堂过夜，门外有人求开门、没开
4. T06 门现爪痕、捡到"天黑去井边"的纸条
── ⟳ 此处发生回溯：时间拨回第1天下午，以下是重走 ──
5. （重走）T04 这次没去看井，直接去了茶馆……
```

## 9. 道具 / 玩法知识注入（不另开常驻 prompt）

**真相源是 `Item_Database_Sheet.xlsx`。程序读 xlsx，把用法填进状态字段，不把知识复制成第二份 prompt 喂模型。**

- **`inventory` / `shop_catalog` 每项带 `usage`**（该道具怎么用，取自 xlsx）。模型谈到玩家已有/在售的道具时，照 `usage` 说，不自行编。
- **`op_hint`**：当前**可做的多步操作**的步骤提示，**在该操作可用的节点才注入**（用得着才给，模型没拿到就不会凭空教，也避免超前）。例：
  - 挂红布：把红布拖到祠堂门口（临时挂住几秒）→ 趁这几秒把铁钉拖到红布上钉死。
  - 锻造匕首：精铁 + 锻造火炉拖到操作台合成（仅祠堂能成）。
  - 烧线头：把线头拖到火上点燃验证。
  - 三个小玩法（倒茶/窃听/追击）的操控说明。
- `usage`/`op_hint` 的具体文案从 xlsx 抽（含道具效果、积分价、库存）。建议程序生成后人工校一遍。

## 10. 安全兜底（prompt 防不住的那层，主防线在程序）

- **双向内容审核**：玩家输入进模型前、模型输出回玩家前，**各过一道审核**（可接 Moderation API 或本地分类器）。命中仇恨/露骨色情/真实可操作的自残方法/政治敏感 → 拦截或重生成。这是 prompt 拦不住的攻击（谐音、套娃、绕话）的主防线，**对外公开有真实玩家时务必上**。
  - ⚠️ **别误伤恐怖剧情**：咬舌、跳井、幻觉、人皮等是本游戏的正常氛围，审核阈值要给恐怖留口子，否则会把正常剧情判敏感。
- **玩家输入只进 `player_input` 字段、当纯文本处理**：做转义，过滤控制符与分隔符（如 `<|im_start|>`、`[INST]` 等），**斜杠命令（`/clear`、`/reset` 等）绝不在程序层当指令执行**——它们只是玩家打的字。
- prompt 侧已有"边界与抗干扰""输出红线"兜着模型自身行为，但**程序审核层才是硬防线**。
